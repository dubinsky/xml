= org.podval.xml
:toc:
:toclevels: 3

Dialect-aware XML for Scala 3: parse, write, transform, and bind documents.

Maven coordinates: `org.podval:org.podval.xml:0.3.0`

----
implementation 'org.podval:org.podval.xml:0.3.0'
----

`zio-blocks-schema` comes in transitively (`XmlCodec`).
`zio-blocks-schema-xml` does not: it is only for the `ZioBlocksXml` adapter.
Each AST given is on its object, not in the package.
Bring one in with `import Xml.given`, `import ZioBlocksXml.given`, `import ZioBlocksHtml.given`, or
`import ScalaXml.given`.
`import org.podval.xml.dsl.given` summons `Xml`.
ZIO Blocks XML, ZIO Blocks HTML, and Scala XML need an extra dependency, not pulled in by default.
`parseHtml` needs TagSoup (also not on the POM):

----
implementation "dev.zio:zio-blocks-schema-xml_3:0.0.51"
implementation "dev.zio:zio-blocks-html_3:0.0.51"
implementation 'org.scala-lang.modules:scala-xml_3:2.5.0'
implementation 'org.ccil.cowan.tagsoup:tagsoup:1.2.1'
----

== Packages

One artifact (`org.podval:org.podval.xml`).
It will not be split into separate Gradle or Maven modules; consumers depend on this coordinate and import the
packages they need.

`org.podval.xml`:: owned AST `Xml`, plus `XmlAst` adapters for ZIO Blocks XML, Scala XML, and ZIO Blocks HTML.
Construction DSL (`org.podval.xml.dsl`) builds `Xml` only.
SAX parser (CDATA preserved) and builder, both over any `XmlAst`; writer; `Xml2Html`; Schema-derived document binder
(`XmlCodec`).
`org.podval.metadata`:: multilingual `Name` / `Names` / `HasNames` / `Language` catalogs (`HasName` is the default-name
key).
`org.podval.store`:: in-memory named tree; `resolve` / `attempt` / `resolveOption` / `getPaths` (`Path.toUrl` is the
encoded English-name URL from the node you called, with selector hops; `resolve` may omit a hop when the name is
unique).
Numbered URL names stay digits; extra names in `number2names` still round-trip.
`Selector` is data (`plural` / `pluralOrNames`); each consumer has a `Selectors` catalog.
`object Selectors extends Selectors` loads `Selector.xml` / `<Selector>` next to that class.
`By(name)` and `By.Numbered(name, min, max, name2number, number2names)` need `given Selectors`; unknown names fail.

== Parse

`XmlParser` loads from a string or classpath resource into any `XmlAst` (`E` from the expected type).
There is no package-level default.
Import `Xml.given` for the owned tree, `ZioBlocksXml.given` for ZIO Blocks XML, `ZioBlocksHtml.given` for ZIO Blocks
HTML, or `ScalaXml.given` for Scala XML.
Convert with `element.to[TO]` (`element.to[ZioBlocksHtml.Element]` after `import ZioBlocksHtml.given`).
`parseHtml` uses TagSoup (HTML only: no namespaces, names are lower-cased; not for TEI).
`xi:include` is not expanded (`xi:include/@href` stays a page ref).
`parseXml` returns the document element; `parseXmlDocument` keeps the declaration, doctype, and comments/PIs before and
after the root so a document can round-trip through the writer.
Parse/decode I/O is `Either[XmlError, _]`; `XmlError` wraps the cause.
`loadCatalog` / `loadResources` throw (programmer catalogs); `attemptCatalog` / `attemptResources` stay in `Either`.
Unknown `By` names and unmatched catalog keys throw.

== Catalogs

A catalog is a wrapper element whose children are one record type (`XmlCodec.decodeCatalog`).
`XmlParser.loadCatalog` reads that file from the classpath and *throws* on a missing resource or a decode error
(`attemptCatalog` returns `Either`).
Catalog helpers pin `Xml`.

=== File and wrapper name

`loadCatalog(from, codec)` takes the name from `XmlParser.className(from.getClass)` (trailing `$` stripped:
`Selectors$` → `Selectors`):

* resource: `from.getClass.getResource(name + ".xml")` — next to *that class*, not a library-wide path
* wrapper: element named `name` (local name / qName)

So `object Foo` looks for `Foo.xml` with root `<Foo>`.
Child tags come from the codec (`Selector.codec` → `<selector>`, `Names.codec` → `<names>`).
Comments and whitespace between children are ignored; leftover character content is an error.

When the Scala object is not named after the file, pass the name (`loadCatalog(this, "Selector", codec)`).
`object Selectors extends Selectors` does that by default.
`loadCatalog(this, Selector.codec)` from `object Selectors` would look for `Selectors.xml` / `<Selectors>` and fail.

`loadCatalog` is `parseResource` plus `decodeCatalog`.
Use `decodeCatalog(root, name)` when the tree is already in hand.

=== Selectors (store axes)

`Selector` is data.
This library has no `Selector.xml`.
Each consumer owns a catalog.
Put `Selector.xml` next to the class (`src/main/resources/org/example/Selector.xml`).
`forName` / `getForName` match any language name (`книга` finds `book`).
`getForName` throws if missing.
Optional `<plural>` children are `Selector.plural`; `pluralOrNames` is that plural, or singular `names` when absent.

`By("book", stores)` and `By.Numbered("chapter", min, max)` summon `given Selectors`.
A nested package does not see a parent-package given; keep the given on the object and `export` it
(`export` of `given` from a *package* is not allowed):

----
package org.example

object Selectors extends org.podval.store.Selectors:
  given org.podval.store.Selectors = this

package tanach:
  export org.example.Selectors.given
----

`By(selector, stores)` and `By.Numbered(selector, min, max)` do not use a catalog.
`By.Numbered(name, min, max, name2number, number2names)` looks the selector up, then passes custom names.

Tests can skip XML: `given Selectors = Selectors(Selector(Names("book")), Selector(Names("part")))`.

=== Names catalogs

`Names.Loader[Key]` loads `<names>` children and binds them to `valuesSeq` with `HasName.mapByName`
(each `<names>` must uniquely match a key's `.name`; every key must match).
Default file is the loader's class name: `object Language` → `Language.xml` / `<Language>`.
Pass `resourceNameOverride` for a different file.
`toNames` is lazy so a catalog can mention values of the same loader.

`HasNames.ByLoader` is the per-value hook (`Language.English.names`).

== XInclude

This library does not expand `xi:include`.
JDK SAX is XInclude-unaware.
Publisher `store`/`collection` indexes treat `xi:include/@href` as a child page reference.
Xerces nested `xml:base` is still wrong (https://issues.apache.org/jira/browse/XERCESJ-1102); see CHANGELOG.

== Codec

`XmlCodec` is a ZIO Schema `Deriver` that binds Scala records to XML documents (unwrapped sibling sequences, attributes
on leaf records).
An unannotated primitive is an attribute named after the field.
Identity fields are `Xml.Element` (child tag = field name); `import XmlCodec.given` (or `import org.podval.xml.given`)
for `Schema[Xml.Element]`.
Encoding that field needs `import Xml.given` (or `import org.podval.xml.dsl.given`).
Leftover parent content is an error unless `@Modifier.config(XmlCodec.IgnoreUnknown, "")`.
`@Modifier.config(XmlCodec.Include, "")` on `Seq[String]` gathers `xi:include/@href`.
Binding hints are `@Modifier.config` (`XmlCodec.Attribute`, `XmlCodec.Element`, `XmlCodec.Text`,
`XmlCodec.NamespaceUri`, `XmlCodec.NamespacePrefix`).
`Name` / `Language` / `Language.Spec` have `Schema` givens (`Names` has `XmlCodec` only); catalog DTOs use
`Seq[Name]`.
`XmlCodec.derived[A, K](tagField, tag)` is picked up when `A` is nested; pass `Child.codec` to
`XmlCodec.derived(nested)` so the child codec is initialized (`Schema.derived` inlines nested records).
`XmlParser.loadCatalog(from, resourceName, codec, wrapperName)` when the file and root tag differ; `loadResources`
decodes one document per `name.xml`.
`transform` / `gather` skip `<code>` subtrees by default (`stopAtCode = true`); pass `false` to walk into them
(publisher IR).
`rewrite` uses that same default and can keep one element or replace it with a node list.

== XML processing

=== XML generation

Construction of wrappers around parsed XML lives on `XmlAst`.
The DSL was inspired by https://github.com/zio/zio-blocks[ZIO Blocks HTML] (`zio-blocks-html` 0.0.51:
tag functions, `:=` / `+=`, `ToModifier` flattening, `.when`, `inlineJs` / `externalJs`).
`import org.podval.xml.dsl.{*, given}` (or `Xml.div`) builds the same tree as parsed markup.

----
div(className := "toc", h3("Table of Contents"), ul(items))
script(typeAttr := "module").inlineJs(code)
element("urlset", xmlns := ns, urls)
----

I tried https://com-lihaoyi.github.io/scalatags/[ScalaTags] for generation, and they work, but there is no clean
https://github.com/lihaoyi/scalatags/issues/102[interoperability] with parsed XML, so generating HTML wrappers for XML
parsed from files is not pleasant.
A second HTML AST (including zio-blocks-html as a construction-only tree) has the same problem.
This DSL builds `Xml.Element`.
Another AST is `element.to[TO]`.

Convert another AST with `element.to[TO]`
(HTML: `element.to[ZioBlocksHtml.Element]` after `import ZioBlocksHtml.given`).
`HtmlXmlWriterConfig.render` is the inherited generic `XmlWriterConfig.render[E: XmlAst]`.
Write a `ZioBlocksHtml.Element` with `import ZioBlocksHtml.given`.

=== XML pretty-printing

Scala XML does provide a pretty-printer, but it doesn't do what I need it to do, especially when formatting TEI
documents.
For instance, it inserts a break between `</e1>` and `<e2>` in `<e1>...</e1><e2>...</e2>` and between `</e1>` and `text`
in `<e1>...</e1>text`, thus separating notes from what they are notes on and punctuation from its content by spaces.
Attempts to modify the behavior of the Scala XML pretty-printer (or at least to fix what looks like an obvious bug in
its `Print.merge`) were not successful, so I started looking for alternatives.

https://www.lihaoyi.com/post/CompactStreamingPrettyPrintingofHierarchicalData.html[Compact, Streaming Pretty-Printing of Hierarchical Data]
looked promising, but it looks like to fine-tune behavior of the pretty-printer, I'd have to rework the code each time:
as with ScalaTags, https://www.lihaoyi.com[Li Haoyi's] focus seems to be performance, but I need flexibility to get the
format I want without rewriting the whole algorithm for each experiment...

I remembered a paper by http://homepages.inf.ed.ac.uk/wadler/[Phil Wadler] on pretty-printing:
https://homepages.inf.ed.ac.uk/wadler/papers/prettier/prettier.pdf[A prettier printer], and almost started implementing
it in Scala, but it turns out that there is an implementation already:
https://github.com/typelevel/paiges[Typelevel Paiges].
With its declarative approach, I was able to tweak the output to my liking :)

A declaration is written only when that prefix is not already bound to the same URI.
A name with no URI does not gain a synthesized `xmlns=""`.
An empty element is `<e></e>` unless its local name is in `selfClose`, or `selfCloseEmpty` is set.
`HtmlXmlWriterConfig` leaves `selfCloseEmpty` off, so an empty `script` stays `<script></script>` and `br` stays
`<br/>`.
