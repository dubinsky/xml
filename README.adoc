= org.podval.xml
:toc:
:toclevels: 3

Dialect-aware XML for Scala 3: parse, write, transform, and bind documents.

Maven coordinates: `org.podval:org.podval.xml:0.0.2`

----
implementation 'org.podval:org.podval.xml:0.0.2'
----

`zio-blocks-schema` and `zio-blocks-schema-xml` come in transitively (`XmlCodec`, `XmlParser`).
`given Html` and `given ScalaXml` need an extra dependency, not pulled in by default:

----
implementation "dev.zio:zio-blocks-html_3:0.0.51"
implementation 'org.scala-lang.modules:scala-xml_3:2.4.0'
----

== Packages

`org.podval.xml`:: AST (`XmlAst`) over ZIO Blocks XML, Scala XML, and HTML; SAX parser (CDATA preserved) and builder, both over any `XmlAst`; writer; `Xml2Html`; Schema-derived document binder (`XmlCodec`).
`org.podval.metadata`:: multilingual `Name` / `Names` / `Language` catalogs.
`org.podval.store`:: in-memory named tree and path `resolve`.

== Parse and catalogs

`XmlParser` loads from a string, URL, file, or classpath resource into any `XmlAst` (`E` from the expected type, or a unique given). If `Html` and `Xml` are both in scope and the expected type does not flow (for example through `match`), write `parse[Xml.Element](...)`. `xi:include` is not expanded (`xi:include/@href` stays a page ref). `parseXml` returns the document element; `parseXmlDocument` keeps the declaration, doctype, and comments/PIs before and after the root so a file can round-trip through the writer.

A catalog is a named wrapper whose children are one record type: `codec.decodeCatalog(root, name)` or `XmlParser.parseCatalog(resource, name, codec)`.

== XInclude

This library does not expand `xi:include`. JDK SAX is XInclude-unaware. Publisher `store`/`collection` indexes treat `xi:include/@href` as a child page reference.

Xerces was not an option:

This is mind-bogglingly weird, but:

* Xerces has a bug in the handling of XIncludes
* starting at the third level of nested includes, the values of the xml:base attributes are wrong
* the bug https://issues.apache.org/jira/browse/XERCESJ-1102 was reported in October 2005!!!
* a patch that allegedly fixes the issue is known for years
* a comment from the Xerces maintainer says:
  What Xerces needs most is new contributors / committers who can volunteer their time and help review these patches and get them committed.
  We also need a new release. It's been 5 years. Long overdue.
  If you or anyone else is interested in getting involved we'd be happy to have you join the project.
* latest release of Xerces was in 2023, with the bug still there
* many projects depend on Xerces, including Saxon, where the bug was also discussed: https://saxonica.plan.io/issues/4664
* allegedly, the bug is fixed in "SaxonC 11.1" - although how can this be with Saxon not shipping its own Xerces is not clear.

So, I need to process XIncludes myself instead of relying on the industry-standard Xerces!
What a nightmare...

We do not: there is no expander here.

== Codec

`XmlCodec` is a ZIO Schema `Deriver` that binds Scala records to XML documents (unwrapped sibling sequences, attributes on leaf records, leftover `XmlExtras`, `XmlNode` identity). Binding hints are `@Modifier.config` (`XmlCodec.Attribute`, `XmlCodec.Element`, `XmlCodec.Text`).
