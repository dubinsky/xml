= org.podval.xml
:toc:
:toclevels: 3

Dialect-aware XML for Scala 3: parse, write, transform, and bind documents.

Maven coordinates: `org.podval:org.podval.xml:0.0.2`

----
implementation 'org.podval:org.podval.xml:0.0.2'
----

`zio-blocks-schema` and `zio-blocks-schema-xml` come in transitively (`XmlCodec`, `XmlParser`).
`given Html` and `given ScalaXml` need an extra dependency, not pulled in by default:

----
implementation "dev.zio:zio-blocks-html_3:0.0.51"
implementation 'org.scala-lang.modules:scala-xml_3:2.4.0'
----

== Packages

`org.podval.xml`:: AST (`XmlAst`) over ZIO Blocks XML, Scala XML, and HTML; SAX parser (CDATA preserved) and builder, both over any `XmlAst`; StAX parser (CDATA not preserved); writer; `Xml2Html`; Schema-derived document binder (`XmlCodec`).
`org.podval.metadata`:: multilingual `Name` / `Names` / `Language` catalogs.
`org.podval.store`:: in-memory named tree and path `resolve`.

== Parse and catalogs

`XmlParser` loads from a string, URL, file, or classpath resource into any `XmlAst` (`E` from the expected type, or a unique given). If `Html` and `Xml` are both in scope and the expected type does not flow (for example through `match`), write `parse[Xml.Element](...)`. XInclude is off unless `xinclude = true` (store `xi:include/@href` stays a page ref). Expansion is implemented here, not via Xerces; `xml:base` on included roots is relative to the initial document. `parseXml` returns the document element; `parseXmlDocument` keeps the declaration, doctype, and comments/PIs before and after the root so a file can round-trip through the writer.

A catalog is a named wrapper whose children are one record type: `codec.decodeCatalog(root, name)` or `XmlParser.parseCatalog(resource, name, codec)`.

== Codec

`XmlCodec` is a ZIO Schema `Deriver` that binds Scala records to XML documents (unwrapped sibling sequences, attributes on leaf records, leftover `XmlExtras`, `XmlNode` identity). Binding hints are `@Modifier.config` (`XmlCodec.Attribute`, `XmlCodec.Element`, `XmlCodec.Text`).
